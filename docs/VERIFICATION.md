Remote-only offscreen regressions check premultiplied alpha, varied edge coverage, identical repeat frames and ring holes at three scales, and export light/dark comparisons. Focus regression **0.1.10**: user reported the 0.1.9 notification “Windows did not allow the radial to receive focus; invocation cancelled.” after the unsafe input-queue attachment fallback was removed. The overlay now uses `WS_EX_NOACTIVATE`/`SW_SHOWNOACTIVATE`, receives navigation/selection through its existing input worker, and retains the invocation's foreground window as the gesture context. A foreground change or fullscreen transition cancels the session. No attempt is made to attach input queues or force the radial into foreground. The native smoke script's focus expectations and END-03/user guide were updated accordingly. A remote-only native regression uses the production runtime/window procedure to open, navigate and cancel, asserting that the foreground stays unchanged; its fixture installs no global hooks and disables chimes. Local validation only compiles this native regression; it is executed on the remote Windows runner. No local app window, cursor movement or input synthesis was used for testing.

Incident/correction **0.1.9**: user identified right-clicking the tray icon as a reproducible trigger for the desktop-wide input blackout. All Constellation processes were forcibly stopped at the user's request and remained stopped during development. The Explorer restart in the Windows log was performed by the user, not evidence of an independent Explorer crash.

The tray handler held `DispatchGuard` plus a mutable runtime reference across `TrackPopupMenu`. Its native modal loop could repeatedly retrieve/re-post foreground, capture, cancellation and input notifications while the original guard could not release. The popup now consumes/releases its guard before native menu tracking, with shortcut invocation suspended until a separate menu-completion message restores registration and handles the chosen command. Reentrant work in the resident/editor is retained in a thread-local pending queue and published only when the outer guard releases; replaceable adjacent state events coalesce, command ordering is retained, and undeliverable owned payloads are released. Deferred application messages are consumed instead of also invoking default processing. The `AttachThreadInput` focus fallback was removed; ordinary Windows focus requests fail gracefully instead of connecting input queues to another app.

Three new local isolated-thread regression tests pass: the actual resident reentry routes retain foreground/capture notifications and convert pointer-bearing DPI notifications to a private pointer-free wakeup; a simulated nested message pump cannot retrieve/re-feed retained events, and 1,000 resize notifications coalesce while both commands remain in order. Existing Quit/message-drain checks also pass. These tests install no hooks and create no windows. A separate remote-only native popup regression invokes the production menu implementation, verifies dispatch availability inside `WM_ENTERMENULOOP`, and ends the menu with a timer without input synthesis; it complements the existing default-resize/dialog-close regression. Exact tray usage, fullscreen pass-through, hotkey focus and manual drag/resize remain to be confirmed after this version. No local Constellation instance was launched to test it.

Follow-up **0.1.8**: the user narrowed the remaining click pause to launching Configure, maximizing, then dragging the maximized titlebar so Windows restores the window. The user also reports the same symptom while resizing by dragging window borders. Earlier reports of a resolved stall did not cover these native move/size paths. Default window processing still held the application dispatch guard across Windows' modal move/size loop. Nested layout/input notifications could therefore be re-posted while the same outer guard stayed held, starving normal interaction. Default processing now releases that guard after the last use of application state in all editor dialogs and the resident window. The remote-only native regression also verifies that a real default `WM_WINDOWPOSCHANGED` → `WM_SIZE` reentry immediately updates the actual editor layout before any posted-message pump, as well as retaining the dialog-close checks. The exact visible drag-from-maximized gesture remains a manual check; no local desktop automation was run.

Investigation **0.1.7**: the user reported an apparent freeze while editing/saving a mouse binding. Read-only inspection found only the separate Configure process running; its main window was responsive but disabled, with no profile dialog present. Windows application logs contained no matching crash/hang record. The main window was re-enabled in place to recover the session without terminating it. Saved configuration was intact (`Ctrl+Q`, cursor-end `leave`); no user configuration was rewritten. The running editor title still identified 0.1.5.

Root cause in close handling: `DefWindowProc(WM_SYSCOMMAND/SC_CLOSE)` synchronously sends `WM_CLOSE`. The reentry guard previously passed the nested close to default processing, destroying an owned dialog without its owner-reenable/state cleanup. Nested closes are now posted for later handling and consumed during reentry in the profile/JSON/main editor and resident procedures. A hidden-window regression using the actual editor/profile window procedures is compiled locally but runs only on the remote Windows CI runner; it exercises the real system-close path, owner reenable, draft disposal and unchanged configuration. No local desktop test was run. Existing stage diagnostics are optional (`--trace-editor`); no trace was active in this incident.

Investigation **0.1.5**: the previous resize path re-posted synchronous `WM_SIZE` notifications while changing scrollbar visibility and laying out controls. Preview rendering is synchronous and is a second possible delay for large trees. `--configure --trace-editor` optionally writes a bounded local stage/timestamp trace to distinguish native layout churn from expensive painting during manual reproduction. No interactive tests were run and no running user app was stopped or replaced.

## Implemented

- Shared Rust configuration model, validation, radial geometry/hit testing, navigation state, and portable storage.
- Native Windows tray, global keyboard/mouse bindings, input consumption, centered overlay/cursor, restoration, and fullscreen suspension.
- Continuous subdivision with saved geometry; dots, parent/child lines, and generated pentatonic bell feedback.
- A separate native configuration process: item editing/reparenting/order, four numeric/slider spacing controls, monitor preview with full fan-out and advisory overflow/narrow/overlap warnings, sound controls, graphical shortcut profiles with keyboard/mouse recording, native pickers/drop, quoted argument fields, bounded undo/redo, validated import/export, and advanced JSON.
- Stable profile IDs with legacy migration; repaired saves preserve valid backups. Local save/backup/recovery and a portable ZIP packaging command. New configuration is signaled to the resident process; changes are deferred during an active radial gesture.
- Lock/disconnect/suspend cancellation and input resynchronization on resume; late selection checks; a dedicated blocking input thread to keep hook delivery independent of disk I/O, launch and rendering work; taskbar icon recreation; explicit empty-Constellation feedback.

## Verify when back at the PC

- Gesture precision with the real tree, large/narrow fans, and rapid cross-branch movement.
- Cursor placement/restoration across the actual monitor arrangement, display scaling, and disconnected displays. Lock/suspend/display/capture tests deliver synthetic notifications to the isolated app; they do not physically lock, sleep, disconnect, or reconfigure this PC.
- Fullscreen suspension with the user's actual games/apps. Detection is a native window/style heuristic; the automated check covers a controlled borderless fullscreen window.
- Bell timbre, loudness, mute, and rapid-note feel. The current mixer allows up to 32 overlapping voices and drops new requests at saturation without stealing playing voices. Desktop tests mute audio and do not establish perceived audio quality.
- Program, URL, folder, shortcut, and script targets using real user configurations. Automated launches cover controlled programs, Python/batch/PowerShell scripts, and a generated Windows shortcut; URL/folder routing is checked without opening user handlers.
- Direct portable-folder write behavior under additional policies/filesystems. Checks cover relocation, foreign working directory, redirected alternate-storage sentinels, malformed data, and a real NTFS write denial. Sentinel checks detect writes to the tested environment paths; they are not a system-wide filesystem trace.

## Current limits

- Supported bindings are documented in the user guide. Modifier+mouse combinations and primary-button invocation are not included.
- Extremely dense full previews still incur native drawing cost (about half a second for 10,000 sectors in this sample); warnings do not change the saved geometry or remove targets.
- Themes, custom icons/images and compatible-program actions are researched in [the personalization study](PERSONALIZATION-STUDY.md), not implemented controls.
- The configuration window uses styled native controls. Updated scrolling, cached preview rendering, small-window reachability, mixed-DPI behavior, contrast and keyboard focus require manual review in this revision.
- Script runners must already be installed. Batch metacharacters are rejected to avoid unintended shell interpretation; a shortcut wrapper can handle advanced cases.
- No installer, startup registration, automatic updater, or Linux desktop adapter is included.

# Constellation 0.1.47 — input recovery and moving-pointer invocation

## Changes

- Pointer movement is accepted only once invocation has centered the cursor and prepared the radial. Queued motion reads the current cursor rather than replaying old screen positions. Releasing a Hold binding before opening finishes cancels instead of selecting from an old position.
- Cursor-confinement checks use Windows’ clip rectangle; ordinary movement immediately after centering no longer causes a false confinement error.
- Resynchronize keyboard/button state on foreground transitions and recovery from a blocked window. A missed foreground notification triggers a coalesced asynchronous recheck, preserving fullscreen protection and input-thread isolation.
- A bounded `data/input-state.log` records foreground window classes and blocking decisions for intermittent failures. It contains no key values, window titles or launch URLs.
- Includes the local 0.1.46 website-favicon feature: Automatic HTTP/HTTPS Stars fetch site icons in a separate worker and cache them inside the portable folder. No config migration or new third-party crates.

## Verification and pending checks

Focused device-free tests cover F13 recovery after a missed release, truly held keys, pending-open motion/release ordering, observer rechecks and clipping bounds. The existing interactive native fixture was updated to exercise stale-motion rejection but was not run on the user’s desktop.

Manual review is still needed for the reported Task Manager → Desktop sequence and invocation while moving the mouse. The exact cause of yesterday’s transient Desktop failure was not captured; elevated-window limitations remain subject to Windows. Fullscreen exclusion remains intentional. Portable bundle transfer, intermittent audio clicks and the rare selection/save issue still await manual reproduction; the small-screen footer redesign remains deferred.
